**Written 2026-11-24**, the day after the three-system read. Inputs:
[`DECISION-2026-11-23.md`](DECISION-2026-11-23.md) (the 18-item take list and the port arithmetic),
the architecture review (`/tmp/opencode/architecture-review-2026-11-23.html`, 8 deepening cards),
the external notes (`agentic-graphrag.md`, `hindsight.md`, `obsidian.md`), and today's baseline
measurements (`bench/p1/graph-ab-baseline-2026-11-24.log`).

**Store migration: what it actually costs.** Nothing is re-ingested. Every schema move below is an
additive `ALTER`/`CREATE` that Postgres applies instantly to a 37,294-row store, and the codebase
already runs its DDL as `create table if not exists` + one-statement-per-entry (`_PG_DDL`). **No
facts are deleted**: the retire-not-delete law keeps 6,684 superseded rows beside the 3,819 active,
and they stay.

| phase | change | migration | instrument | falsifier |

| 1 | three-source graph | none | `m4_concept_ab.py` | the walk does not move top-8 |

## Phase 1 — the graph reads all three of its edge sources (DONE 2026-11-24)

**The measured diagnosis.** The store has carried three kinds of connection and the ranking read
two:

| source | size on this store | read by the arm before today |
|---|---|---|
| the built LLM graph | 3,133 edges, 4,239 nodes (2,326 rows, 1,913 concepts) | **1,020 (33%)** — an edge survived only if both ends parsed as rows |
| the vectors | 3,755 facts, k=8 in **0.423 s**, 15,020 edges | on by config? **no** — `graph_sim_k` is unset, so 0 = off |
| the typed `links` table | **858 rows, all `kind='about'`** | **none** — text on the hit line only |

Three fixes, all in `serve/memory.py`, all pinned by tests in `serve/test_graph.py` (21 green):

1. **Walk the concept nodes** (`_graph()`). Adjacency is now an **ordered list**, priced
   direct-edge and same-case first, then the **tightest shared concept** (a bridge over two rows
   outsells a hub over thirty), capped at `CONCEPT_FAN` (12) per row. The 2,113 dropped edges
   become 2-hop bridges.
2. **Price the ladder, not the row number** (`_graph_expand()`). The vote pays position, and the
   neighbourhood was `sorted()` by row id — so the price was an accident of insertion. Now: typed
   edge → graph edge → vector neighbour.
3. **The typed edge votes** (`_link_neighbours()`, new). One SQL read over `links`, both directions,
   both ends active, `contradicts`/`supports` ordered ahead of `about`, capped at `LINK_FAN` (8),
   **filtered by the ask's scopes** — the law the graph read already applied and the link read did
   not (14 active links cross scopes on this store).

**Baseline (before, `m4_graph_ab.py`, 60 linked probes, arm off → on at 0.45):** mean rank
40.93 → 35.77, top-8 **5/60 → 13/60**, 21 up / 1 down. Adding `sim_k 8` changed nothing (13/60),
so the vector layer stays off by default — a measured tie, not a guess.

**The walk, measured with the probe set fixed** (`tools/m4_concept_ab.py`, new: 200 probes cut at
fan 12, one variable swept): arm off 11/200 top-8; **fan 0 (direct edges only) 15/200, 23 up / 3
down; fan 12 (full walk) 16/200, 25 up / 3 down.** The walk pays, modestly, and costs nothing extra
— the price ladder keeps the direct edges in front. Fan 4 ties fan 12, so 12 is chosen for the
coverage, not the score.

### 1b. What the three-source ladder bought, and the weight it moved

The 250-probe neighbourhood set (graph-walk pairs **plus** typed-link pairs, the box's own config,
not constructor defaults) is the instrument that measures all three sources at once:

| arm | top-8 | mean rank | median |
|---|---|---|---|
| off | 20/250 | 44.03 | 51.0 |
| `graph_weight 0.45` (the shipped box number) | 32/250 | 23.73 | 19.0 |
| `0.45 + sim_k 8` | 31/250 | 26.43 | 22.0 |
| **`0.8 + sim_k 8`** | **71/250** | **20.46** | **14.5** |

And the control set, where the arm can only cost — 120 served probes (gold = the row the query was
cut from): **117/120 top-8 at every weight** (0, 0.45, 0.8, 1.2), mean 2.35 → 2.45. So the ladder
gains 51 top-8 hits on the neighbourhood set and spends ~0.1 of a rank position on the served set.

**Shipped on the box:** `graph_weight 0.45 → 0.8`, `graph_sim_k` unset → 8 (`strata-heretic-iq4_nl.json`,
a box-local config, so this needs one reboot — **reboot ready**). Stated honestly: the neighbourhood
probes are built *from* graph and link neighbours, so the arm is favoured by construction; the served
set is the control, and it is flat. The outcome number is the venue day.

### 1c. The queue that nothing drained

The harvest has noted new fact ids into `pending.json` since 2026-11-15, and **no timer read them**:
612 rows queued behind a manual 53-minute pass. `tools/sweep_cron.sh` now runs the tick with
`--graphify --graphify-threshold 48`, so a ~48-fact merge pass (~3 min of decode at the measured
273 out-tokens/fact) runs in the idle window instead of a full-store rebuild every few days.

## Phase 2 — two cheap structural wins

### 2a. Compute the time mark; let the model read it

Hindsight's consolidation prompt does not ask the model which fact is newer — it marks the
candidates `(stated after this fact)` and sets `newer_than_input_facts: true`, and its own ablation
is **29/40 → 36-38/40** with no code checks and no second call
(`consolidation/prompts.py:156-162`).

Our clerk sees one turn and a shelf list. Temporal is our worst slice (0.465), and `when` has been
stored to the minute since the start.

- **Change:** in `tools/curate_loop.py`, the supersede/correct candidate list carries a
  `(stated after this fact)` mark computed against `when`, and the prompt says the newest stated
  value wins, not the last processed.
- **Migration:** none.
- **Instrument:** the temporal slice of the venue, three repeats, right-fact-in-block held flat.
- **Falsifier:** temporal moves less than one repeat band while the junk rate rises — the mark bought
  verbosity, not order.

### 2b. Three budgets, one per kind of text

`engine/fact_budget.py` (Hindsight) spends facts, evidence and passages from **separate** caps,
skips an oversized item rather than evicting the tail, and guarantees one whole result. Our block
has one budget (`max_block_chars` 48,000 + `turn_block_chars`), and our own complaint is that it is
"spent on this afternoon's sentences" — 90% of facts are derived, and only 4% of them are never
recalled.

- **Change:** a `doc_chars` cap inside `_render_block` (the `block_doc_cap` per-row cap becomes a
  per-family budget), and an `evidence_chars` cap for the provenance the block prints.
- **Migration:** none.
- **Instrument:** the never-recalled share, plus panel MRR, plus block fill rate at a fixed budget.
- **Falsifier:** the durable tail's recall share does not move.

## Phase 3 — event time, on the edges too

`memories` is bi-temporal (`when`/`created_at` = transaction time; `invalid_at` + `superseded_by` =
the chain). `links` has **`created_at` only** — an edge cannot be dated, so "what did we believe in
October?" is unanswerable for the relations, which is where `contradicts` lives.

- **Change:** `links +valid_at timestamptz +invalid_at timestamptz` (two instant ALTERs), set on
  write and on re-label; `at=` becomes a predicate on both tables; `_render_block` prints the span
  on the line a link rides.
- **Migration:** additive, no rewrite, existing edges read as "valid since `created_at`".
- **Instrument:** the temporal and knowledge-update slices, coverage held flat.
- **Falsifier:** the `at=` filter costs more than the slice gains (the router's lesson: a right pick
  gains ~nothing, a wrong pick filters the gold out).
- **Convergence:** Zep/Graphiti carry the same pair; Hindsight carries `occurred_start/end` +
  `mentioned_at` and ranks on them.

## Phase 4 — shelving: a queue, a caption, and a number

**The measured state:** 91 shelves, **19 of them holding ≤3 rows**, one with 1 row; the clerk's
labeling quality is **unmeasured** (2 of 4 identical asks moved the shelf, temp 0.8); nine files
decide a shelf; 41 `m2_*`/`m4_*` scripts in the kit.

1. **The candidate queue** (agentic-graphrag): a `NEW/CUTTER` answer lands in a `candidates` table
   with its evidence row ids and a sighting count, and a human (or the sweep with a bar) promotes
   it. A rejected candidate is not recreated: key it by content, the way agentic-graphrag keys a
   candidate so the same invention does not return next week.
2. **A caption per shelf** (LCC's scope notes, the item `lcc.md` queued): the `shelves` table
   already has an `anchor` column and MEM/CAT label rows — give the clerk the caption, not just the
   name, and the shelf choice becomes falsifiable.
3. **The label-quality panel** — the number we do not have: ~40 judged asks, trap-first
   (Hindsight's grading rule), same asks twice, reporting shelf agreement and the wild rate. Run it
   before and after any clerk change; it is the interface the Shelving module is tested through.
4. **Bound the clerk's spend** (agentic-graphrag's `ceil(L × 500/10)`): a per-tick ask ceiling,
   reported, with `undecided ≠ rejected` — a clerk that shrugs leaves the row wild, not misfiled.

**Migration:** `create table if not exists candidates(...)` — one table.
**Falsifier for the queue:** the approval rate runs near 100% — then the queue is theatre and the
clerk's first guess was right.

## Phase 5 — the two rungs the store does not have

### 5a. Observations (beliefs that accumulate)

Today a correction **replaces**: the new row wins, the old retires, and 6,684 retired rows sit in the
chain. Hindsight's observation layer **accumulates**: one belief row carries `source_memory_ids` and
a `proof_count` computed as a SQL **set union** (so evidence cannot double-count), and refinement
strengthens, weakens, or extends it.

- **Change:** rows on a new shelf family (`<FAM>/OBS`, or a lane like `fact|taboo|state` — the lane
  is the cheaper shape: no new axis, one subclass), with `provenance.evidence = [row ids]` and
  `provenance.proof_count` as a set-cardinality, written by a sweep pass that clusters facts the
  clerk already files together.
- **The scar:** bounded inline history, the old value as a bracketed annotation capped at 3
  (Hindsight's convention) **plus** our supersession chain — the annotation is for the reader, the
  chain is for the audit.
- **Migration:** one lane value, zero DDL.
- **Instrument:** a new number — **consolidation ratio** = rows in the block ÷ distinct subjects
  covered — plus the panel.
- **Falsifier:** the belief pile grows without shrinking the block's row count.

### 5b. Pages (a standing answer, rewritten in the background)

`always.md` is 55,881 chars of hand-maintained box map, riding every prompt in the cart, aging
against every boot. Hindsight's mental models are exactly this and rewrite themselves: define the
question once, read the answer as a database read, refresh on a delta by asking each memory "could
this change the page?" — and when none can, **no LLM call at all**.

- **Change:** a `pages` table (`question, text, source_row_ids, refreshed_at, version`), one sweep
  pass per page, and the page rendered into the cart in place of its hand-written section. Start
  with one page: **"what is the state of this box?"** → the Live state section of `always.md`.
- **Migration:** one table.
- **Instrument:** cart bytes, and the staleness of the claims inside them (count the Live-state
  lines that name an engine version older than the running one, at boot, over a month).
- **Watch:** Hindsight's issue #5574 — delta pages grow to 3-4× their budget because "the budget is
  a prompt hint only and nothing enforces it". Enforce ours in code, in the render, not the prompt.

## Phase 6 — stop paying 4.5 hours to re-cut the corpus

**The measured cost:** a `--force` pass is 229 s of chunking plus **15,907 s of embedding**
(33,475 rows at 2.1 rows/s). `--force` is needed to re-chunk an untouched folder because the cut
**mode lives outside the stat key** — the ledger stats `(size, mtime, sha256)` and the mode is not
in it.

agentic-graphrag's answer is five hashes and a published "what differs → what re-runs" table, and
the split that matters: **a schema/extraction change re-extracts on existing chunks and keeps the
embeddings.**

- **Change:** `docs +chunker_hash +schema_fingerprint +mode` (three instant ALTERs) and the dispatch
  table: content/structure/chunker/mode ⇒ re-chunk + re-embed; cutter/shelf-map change ⇒ re-shelve
  rows in place (vectors survive — `Docs.set_class` already does this); dates only ⇒ write dates.
- **Instrument:** wall-clock of a forced pass, and rows touched.
- **Falsifier:** the split saves less than the extra bookkeeping costs to keep honest.

## Phase 7 — the vault, one way

A projection, not a fork of truth: shelf → folder, row → note, `supersede_id` → a link to the scar,
`links.kind` → a typed wikilink, `when`/`confidence`/`hits` → frontmatter. The vendored
`graphify export obsidian` already proves the pattern on this box (212,916 notes, 91.0 MB text,
888 MB on disk, ownership manifest with byte-identical-skip and prune), and our Graph tab already
ships the node-as-note interaction with the two things Obsidian lacks: typed edges and confidence.

- **Change:** `tools/m10_vault.py --out ~/vaults/strata` (facts only; the 33,475 chunks stay in the
  corpus files), two `.base` ledgers (the shelf×confidence×hits table, the supersession chain), and
  **a lint**: fail on a fact note with no `when`, no `shelf`, or a `supersedes:` pointing at a
  missing file — OKM's rule that "a linter that fails the build beats a field".
- **Falsifier:** after a month, the vault has not been opened twice.

6. **The standing cart remints 87 times.** `remint_count: 87` on a 720 MB file is ~62 GB of writes —

8. **The copied fact identity.** `curate_loop._norm` is a hand-copy of `serve.memory.norm_text`;

## Optimizations, measured, in order of cost paid

1. **The graph pass is decode-bound**: 273 output tokens per fact at ~90 tok/s; 1,183 facts read per
   pass, 612 queued, store grows 150-234 facts/day. **Run the LLM layer on the queue, not the
   store**: a nightly merge pass over ~200 new facts is ~9 min, not 53, and coverage stops lagging.
2. **1,608 communities over 2,136 rows = 1.33 rows each.** Raise the floor to ≥2 (agentic-graphrag)
   and weight edges by attestation, and the community layer starts summarizing.
3. **Entity resolution at merge** — the owner is three nodes (`Eugene`, `Dustin (goes by Eugene) —
   owner`, `Dustin — the user`) because `_merge_extractions()` concatenates. A cheap name-key fold
   at merge, no LLM.
4. **Five of twelve god nodes are export artifacts** (`USR — part 1 (25 facts)`, degree 26 =
   `FACTS_PER_FILE` + 1). Drop the per-part file node from the graph, or lift the file to a shelf
   node: the batching is a transport format, not a subject.
5. **`m4_*` sprawl**: 41 scripts, each with its own CLI. The panel instruments are the ones worth
   naming in `GLOSSARY.md` (done for the main three); the rest are candidates for a
   `tools/m4 --verb` front.

## Definition of done, per phase

Ship a phase when: tests green in `serve/test_*` (the documented runner, not pytest), the phase's
instrument moved in the named direction with ≥3 repeats and one variable named, the journal carries
the dated line, and the default path stays byte-identical for a box that sets no new knob.
